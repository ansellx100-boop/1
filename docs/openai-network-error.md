# Устранение ошибки ERROR_OPENAI: network_error

Ниже приведены практические шаги, чтобы уменьшить вероятность сетевых
сбоев при обращении к API и корректно обрабатывать кратковременные
разрывы соединения.

## Частые причины

- Нестабильное интернет-соединение.
- Прокси или фаервол разрывают длительные соединения (особенно стриминг).
- DNS сбои или временная недоступность провайдера.
- Сервис временно недоступен (проверьте status.openai.com).

## Рекомендации по устойчивости

1. **Таймауты.** Явно задавайте таймауты на соединение и чтение.
2. **Повторы.** При `retryable=true` повторяйте запрос с экспоненциальной
   задержкой и джиттером.
3. **Стриминг.** Если поток оборвался, повторяйте запрос целиком.
4. **Логи.** Логируйте `request id`, тип ошибки и время повтора.

## Пример логики повтора (псевдокод)

```
maxRetries = 5
baseDelayMs = 500

for attempt in 1..maxRetries:
  try:
    return callApi()
  except NetworkError as err:
    if not err.retryable:
      raise
    sleep(jitteredExponentialDelay(baseDelayMs, attempt))

raise LastNetworkError
```

## Что проверить в окружении

- Прокси и сертификаты (MITM-прокси часто ломают стриминг).
- DNS (попробуйте 1.1.1.1 или 8.8.8.8).
- Ограничения в корпоративной сети.

## Минимальная диагностика

1. Повторите запрос без стриминга.
2. Проверьте, воспроизводится ли ошибка из другой сети.
3. Сравните частоту ошибок с данными status.openai.com.
